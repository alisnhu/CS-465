
Architecture

In my full stack project, I used three different methods for frontend development: Express HTML, JavaScript, and Single Page Application (SPA). Express HTML allowed me to create static pages on the server side. Throughout the project, I used the MEAN stack (MongoDB, Express, Angular, Node), and since all these technologies are fundamentally based on JavaScript, the JavaScript language became the core component throughout the project, including backend, database, and frontend. SPA, on the other hand, loads only a single HTML page and dynamically updates the data through API calls, providing a smoother user experience. While SPA offers a faster and more user-friendly experience compared to other methods, Express HTML provided a more traditional approach. However, due to SEO optimization issues with SPA, I had to use both approaches simultaneously: Express for publicly accessible pages and SPA (Angular) for the admin panel.

The backend used a NoSQL MongoDB database because it provides flexibility and scalability. MongoDB's document-based structure allows dynamic data storage without adhering to a strict schema, giving significant flexibility in data storage. However, due to the variable schema, additional precautions might be required when displaying data. Additionally, MongoDB's ability to process large amounts of data quickly and its support for horizontal scaling made it a suitable choice for modern web applications.

Functionality

JSON (JavaScript Object Notation) is a data format that resembles JavaScript but is language-independent. Its syntax is derived from JavaScript object notation. Since it is well-suited for working with objects in JavaScript and provides a lightweight data exchange format, it is used for communication between the frontend and backend. JSON facilitates data exchange between the frontend and backend via HTTP requests, and API responses are typically in JSON format.

During the full stack development process, I improved functionality and efficiency by refactoring the code. For instance, I created reusable user interface components, reducing code redundancy, simplifying maintenance, and accelerating development. For example, the edit form page and signup form page were designed in a way that allowed them to be reused for registration and login processes.

Testing

Various methods are used to test API endpoints in a full stack application. HTTP requests such as GET, POST, PUT, and DELETE are evaluated in different test scenarios. During API testing, validation of sent and returned data, error handling, and response times are checked. In terms of security, authentication and authorization processes are included as additional layers in testing. For example, I used JWT (JSON Web Token) to ensure that only authorized users could access specific endpoints and tested this security layer. These tests were conducted in three different phases: 1. Defining the scenario, 2. Testing the services, and 3. Evaluating the functionality of the user interface.
